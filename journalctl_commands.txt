========================================================
        JOURNALCTL COMMANDS - REFERENCE GUIDE
        For Linux System Log Management (systemd)
========================================================

-------------------------------------------------------
1. VIEW ALL LOGS
-------------------------------------------------------
Command : journalctl
Purpose : Displays all system journal logs from the beginning.
          Useful for a full overview of system activity.

-------------------------------------------------------
2. VIEW LOGS IN REAL-TIME (Follow Mode)
-------------------------------------------------------
Command : journalctl -f
Purpose : Streams live log output as new entries are written,
          similar to 'tail -f'. Ideal for monitoring active services.

-------------------------------------------------------
3. VIEW LOGS FOR A SPECIFIC SERVICE/UNIT
-------------------------------------------------------
Command : journalctl -u <service-name>
Example : journalctl -u nginx.service
Purpose : Filters logs for a specific systemd unit/service.
          Great for debugging a particular application.

-------------------------------------------------------
4. FOLLOW LOGS FOR A SPECIFIC SERVICE
-------------------------------------------------------
Command : journalctl -u <service-name> -f
Example : journalctl -u sshd.service -f
Purpose : Combines unit filtering with real-time streaming.
          Used to watch a specific service's activity live.

-------------------------------------------------------
5. VIEW LOGS SINCE A SPECIFIC TIME
-------------------------------------------------------
Command : journalctl --since "YYYY-MM-DD HH:MM:SS"
Example : journalctl --since "2024-01-01 08:00:00"
Purpose : Shows logs from a specific date and time onward.
          Useful for investigating incidents at a known time.

-------------------------------------------------------
6. VIEW LOGS WITHIN A TIME RANGE
-------------------------------------------------------
Command : journalctl --since "start-time" --until "end-time"
Example : journalctl --since "2024-01-01" --until "2024-01-02"
Purpose : Filters logs between two timestamps.
          Perfect for isolating logs during a specific window.

-------------------------------------------------------
7. VIEW LOGS SINCE LAST BOOT
-------------------------------------------------------
Command : journalctl -b
Purpose : Shows all logs from the current boot session.
          Helps diagnose issues that started after the last reboot.

-------------------------------------------------------
8. VIEW LOGS FROM A PREVIOUS BOOT
-------------------------------------------------------
Command : journalctl -b -1
Purpose : Shows logs from the previous boot session (-1 = one boot ago,
          -2 = two boots ago, etc.). Useful for post-crash analysis.

-------------------------------------------------------
9. LIST ALL PREVIOUS BOOT SESSIONS
-------------------------------------------------------
Command : journalctl --list-boots
Purpose : Displays a list of all recorded boot sessions with their
          IDs and timestamps. Helps identify which boot to investigate.

-------------------------------------------------------
10. FILTER BY LOG PRIORITY/SEVERITY LEVEL
-------------------------------------------------------
Command : journalctl -p <level>
Example : journalctl -p err
Levels  :
  0 = emerg   (System is unusable)
  1 = alert   (Immediate action required)
  2 = crit    (Critical conditions)
  3 = err     (Error conditions)
  4 = warning (Warning conditions)
  5 = notice  (Normal but significant)
  6 = info    (Informational messages)
  7 = debug   (Debug-level messages)
Purpose : Filters logs by severity. Useful to quickly find errors
          or warnings without sifting through all messages.

-------------------------------------------------------
11. VIEW KERNEL LOGS ONLY
-------------------------------------------------------
Command : journalctl -k
Purpose : Shows only kernel-level messages (dmesg-like output).
          Useful for diagnosing hardware or driver issues.

-------------------------------------------------------
12. VIEW LOGS FOR A SPECIFIC PROCESS ID (PID)
-------------------------------------------------------
Command : journalctl _PID=<pid>
Example : journalctl _PID=1234
Purpose : Filters logs generated by a specific process.
          Helpful when debugging a known running process.

-------------------------------------------------------
13. VIEW LOGS FOR A SPECIFIC USER
-------------------------------------------------------
Command : journalctl _UID=<user-id>
Example : journalctl _UID=1000
Purpose : Shows logs related to a specific system user.
          Useful in multi-user environments for auditing.

-------------------------------------------------------
14. OUTPUT LOGS IN JSON FORMAT
-------------------------------------------------------
Command : journalctl -o json
Purpose : Outputs log entries in JSON format.
          Useful for piping into scripts or log analysis tools.

-------------------------------------------------------
15. OUTPUT LOGS IN JSON PRETTY FORMAT
-------------------------------------------------------
Command : journalctl -o json-pretty
Purpose : Outputs JSON-formatted logs in a human-readable,
          indented structure. Ideal for manual inspection of fields.

-------------------------------------------------------
16. VIEW LAST N LINES OF LOGS
-------------------------------------------------------
Command : journalctl -n <number>
Example : journalctl -n 50
Purpose : Shows only the last N log entries.
          Quick way to see the most recent system activity.

-------------------------------------------------------
17. VIEW LOGS WITHOUT PAGER (Plain Output)
-------------------------------------------------------
Command : journalctl --no-pager
Purpose : Outputs all logs directly to the terminal without
          pagination. Useful for piping output to grep or files.

-------------------------------------------------------
18. CHECK DISK USAGE OF JOURNAL LOGS
-------------------------------------------------------
Command : journalctl --disk-usage
Purpose : Displays the total disk space used by stored journal logs.
          Helps monitor and manage log storage consumption.

-------------------------------------------------------
19. VACUUM LOGS BY SIZE
-------------------------------------------------------
Command : journalctl --vacuum-size=<size>
Example : journalctl --vacuum-size=500M
Purpose : Deletes old journal logs until total size is under the
          specified limit. Frees up disk space automatically.

-------------------------------------------------------
20. VACUUM LOGS BY TIME
-------------------------------------------------------
Command : journalctl --vacuum-time=<duration>
Example : journalctl --vacuum-time=2weeks
Purpose : Removes journal entries older than the specified duration.
          Keeps logs clean and relevant.

-------------------------------------------------------
21. SEARCH LOGS FOR A KEYWORD
-------------------------------------------------------
Command : journalctl | grep "<keyword>"
Example : journalctl | grep "error"
Purpose : Filters log output for a specific keyword or pattern.
          Combines journalctl with grep for targeted searches.

-------------------------------------------------------
22. VIEW LOGS FOR CURRENT USER SESSION
-------------------------------------------------------
Command : journalctl --user
Purpose : Shows journal logs for the currently logged-in user's
          systemd user session (not system-wide).

-------------------------------------------------------
23. VERIFY JOURNAL INTEGRITY
-------------------------------------------------------
Command : journalctl --verify
Purpose : Checks the integrity of journal log files for corruption.
          Useful after unexpected shutdowns or disk errors.

-------------------------------------------------------
24. ROTATE JOURNAL LOGS MANUALLY
-------------------------------------------------------
Command : journalctl --rotate
Purpose : Forces an immediate rotation of current journal log files.
          Often used before vacuuming to ensure cleanup is complete.

-------------------------------------------------------
25. VIEW LOGS WITH FULL METADATA (VERBOSE)
-------------------------------------------------------
Command : journalctl -o verbose
Purpose : Displays log entries with all available metadata fields.
          Provides maximum detail about each log event.

========================================================
   QUICK PRIORITY REFERENCE
========================================================
  emerg   = System crash / completely unusable
  alert   = Must act immediately (e.g., disk full)
  crit    = Critical failure (hardware/software)
  err     = Standard errors
  warning = Potential issues, not yet errors
  notice  = Significant normal events
  info    = General operational messages
  debug   = Detailed diagnostic output

========================================================
   COMMON USEFUL COMBOS
========================================================
  Live errors only:
    journalctl -f -p err

  Service errors since last boot:
    journalctl -u nginx.service -b -p err

  Last 100 lines, no pager:
    journalctl -n 100 --no-pager

  Kernel errors only:
    journalctl -k -p err
